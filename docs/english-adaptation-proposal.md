## 1. 探针怎么做的

- **语料**：7 篇，coding / teaching / writing / discussion / daily / mixed 各 1 篇，加 1 篇展示段落。
  - 都是我按论文列出的难读特征“倒推”写的：名词堆叠、受事关系从句省略 that、无生命主语配有生命动词、动词名词化、电报式省略，以及商务黑话。
  - 每篇标注必须保留的术语和数字，用来量保真。
  - 语料只花了一次手写，没有调用模型生成。
- **桥接语**：日语，与论文一致。论文用 NLLB-200 经日语往返；它的附录 B.5 也用 TranslateGemma-4B 做过稳健性检查。
- **翻译模型（都走 OpenRouter）**：
  - `tencent/hy-mt2-30b-a3b`，现行中文模型；
  - `google/gemma-3-4b-it`，与 TranslateGemma 同尺寸。TranslateGemma 本身在 OpenRouter 上没有；
  - `google/gemma-4-26b-a4b-it`，激活参数和价格都与 hy-mt2 相当。
- **提示词**：混元 MT 官方的“非中文互译”英文模板。

## 2. 翻译模型对比（7 篇平均）

| 指标 | 原文 | hy-mt2-30b | gemma-4-26b | gemma-3-4b |
|---|---|---|---|---|
| 往返耗时 P50 | — | 3.8s | **1.2s** | 2.2s |
| 段回退率（没通过校验、退回原文） | — | **0%** | **0%** | 33% |
| 与原文逐字相同的篇数 | — | 0 | 0 | 3 |
| 词数（越多说明拆得越开） | 62.7 | 79.6 | 81.1 | 71.3 |
| 名词化词 / 百词 | 9.1 | **5.3** | 6.4 | 7.2 |
| 黑话 / 千词 | 63.8 | 14.9 | **13.9** | 34.0 |
| 连字符复合词 / 百词 | 6.4 | **1.5** | 1.6 | 3.0 |
| 超过 30 词的长句占比 | 4.8% | 7.1% | 10.7% | 3.6% |
| 7 篇往返总费用 | — | $0.0008 | $0.0005 | $0.0005 |

**数字**：三个模型各有 3 篇的数字串和原文不一致。逐条看过，全是写法变化，没有改值：
- 3 → three，2 → two；
- 7:00 → 7 a.m.，2 pm → 2:00 PM。
上线时数字校验要把这类写法当成相同。

**语义漂移**：通读发现以下几类。宿主只把往返稿当参考，这些都没有带进定稿：
- hy-mt2：amortized O(1) 被译成 average O(1)；把 “flake-rate-driven CI” 拆成了 “flake-rate-driven and CI”。
- gemma-4：基本不漂移，但也不怎么拆。“drove alignment”“leveraging”“surfaced” 原样留着。
- gemma-3：**把用户的问题写进了正文，覆盖了 “## Fix” 这个标题**；还把 write-path invalidation 译成 write-through。**淘汰。**

**选 hy-mt2 的理由**：
1. 从 v6 起，补丁打在原文上，往返稿只供宿主借用说法。所以往返稿的价值在于**拆得开**：句子更松，名词堆叠和名词化更少。这两项 hy-mt2 最好。保真由宿主负责，hy-mt2 的漂移都在宿主能核对的范围内。
2. 中英文用同一个模型：只有一套提示词兼容问题和一套限长参数，用户也只需要知道一个模型名。
3. gemma-4 快 3 倍，但它保留了原文的说法，等于给宿主的“直白参考”少。可以作为“要求延迟更低”时的备选配置。

**展示段落前后对照（showcase）**：

> **原文**：This sprint, we drove alignment across the identity platform workstream and landed a holistic token-validation path consolidation for `auth-gateway`, unlocking a step-function improvement in tail-latency posture: p99 moved from 120ms to 45ms. …
>
> **定稿**：This sprint, we coordinated work across the identity platform workstream and consolidated the token-validation path for `auth-gateway`. This improved tail latency: p99 moved from 120ms to 45ms. We used a Redis-backed caching layer for session introspection, rolled out across 2 regions. …

**探针暴露的问题**（开发时要修）：
1. **连字符词被当成代码冻结。** 掩码规则里的 kebab 规则（三段以上连字符）原本用来保护 `my-long-flag` 这类标识符。英文正文里的 `north-star-aligned`、`flake-rate-driven` 也被冻结了，宿主想改时补丁被拒（2 条拒收都是它）。展示段落最后一句 “Net-net: a north-star-aligned win” 因此没被改掉。英文模式下，反引号外的纯小写连字符词应改为软保护，或者干脆不冻结。
2. **讨论类长句没拆**：discussion 篇句长从 25 词变成 28 词。宿主把黑话改掉了，但没拆句。英文规则需要和中文 v7 一样，补一条“一句塞太多信息就拆”的具体表现。
3. **英文标点清理缺失**：teaching 篇有一处补丁拼接留下了 “degradation..”。现有清理只覆盖中文标点。
4. **现有代码里的 bug**：`default_translator_factory` 没有把源语言传给翻译器，回程默认译回中文。中文版不受影响，但多语言化时必须修。
5. **英文按句切块不认半角句点**：`split_long` 的句末正则不含 “.”。超长英文段落会退化成按逗号或硬切。

## 4. MCP 双语形态：选型

候选方案：

| 方案 | 怎么判断语种 | 优点 | 缺点 |
|---|---|---|---|
| A. 拆成 en、zh 两个服务（或两组工具） | 宿主挑工具 | 实现最简单 | 安装和配置要做两遍；宿主每次都要挑对，挑错就用中文规则改英文；中英混排时无从选择 |
| B. 一个服务，看待改文本本身 | 按文字占比确定性判断 | 不依赖宿主，结果可复现、可测试；改的是文本，就看文本 | 中英混排时需要阈值 |
| C. 一个服务，看宿主意图或运行时会话信息 | 宿主模型判断，或读会话 | 能照顾“用中文问、要英文稿”这类情况 | MCP 协议不给服务端会话内容或用户语言，服务端只看得到工具参数。说是“读运行时”，最终还是靠宿主传参；宿主判断还会漂移 |

**建议采用 B，并允许宿主用参数覆盖**：
- `prepare_rtt_draft` 新增可选参数 `language: "auto" | "zh" | "en"`，默认 `auto`。
- `auto` 时数待改文本里去掉代码和占位符后的字母：汉字占比 ≥ 30% 判中文，否则判英文。中文正文里夹英文术语仍判中文。
- 宿主明确知道的时候（例如用户要求输出英文稿）可以显式传 `language`。工具描述里写清楚这一点即可，不要求宿主每次都判断。
- 判出的语种决定整套**语言配置**：掩码规则、翻译提示词与校验、桥接语、默认服务商和模型、审校规则、雷达、标点清理。返回结果写明用了哪种语言，便于排查。
- 工具名不变，描述改成中英双语，两种语言的宿主都能读懂。

## 5. Key 与服务商默认值

| 语种 | 默认服务商 | 模型 | 桥接语 | 缺默认 Key 时 |
|---|---|---|---|---|
| 英文 | OpenRouter（`OPENROUTER_API_KEY`） | `tencent/hy-mt2-30b-a3b` | 日语 | 有腾讯云 Key 就用 `hy-mt2-pro`（已实测 EN→JA→EN 能跑，占位符保留） |
| 中文 | 腾讯云（`TENCENTCLOUD_API_KEY`） | `hy-mt2-pro` | 俄语 | 有 OpenRouter Key 就用 `hy-mt2-30b-a3b`（即封存集评测过的配置） |

- 两个 Key 都没有：整体回退，宿主只拿原文和雷达做审校。这是现有行为，不变。
- 用户显式设置的 `NO_AI_FLUFF_PROVIDER` 或 `NO_AI_FLUFF_MODEL` 优先于语言默认值。
- 安装器的提示按语种写：英文用户先提示配 OpenRouter，中文用户先提示配腾讯云。
- 宿主仍只走用户自己的宿主模型（Claude Code 等）；评测时宿主仍按 CLAUDE.md 只走 DeepSeek 官方 API。

**风险（即 D4）**：中文默认改成腾讯云 `hy-mt2-pro` 后，中文的线上默认模型就不再是评测过的那个。建议先在 Dev 24 篇上跑一轮 RTT 客观指标：段回退率、数字一致性、长句、散装英文，再加耗时。不差于 30b 再切换；否则中文默认先留在 OpenRouter。
