# no-ai-fluff-en 评测报告（英文版）

> **当前正式版**：第二代规则 en5（代际名 `v2`），也就是结构雷达 + 领域分诊 + 双通道门控，运行时不带 jargon 词表。2026-11-12 起为默认规则，结果目录 `benchmarks/results/en-test-en5/`（测试集）、`en-r5/`（调参集）。
> 第一代规则 en2（代际名 `v1`）的结果保留作对照：`en-r1/`、`en-r2/`（调参）、`en-test/`（测试集）。
> 复现：`python benchmarks/en_eval.py run --set test --run en-test-en5 --rules en5` → `metrics` → `judge --ref en-test`
> 测试集锁：`benchmarks/splits/en_test.lock.json`。调参开始前写好并锁定 sha256，调参期间没有读过；en2 与 en5 各用过一次。

## 结论（en5，12 篇锁定测试集）

- **对原文胜率 63.1%**，12 篇里 9 篇胜出（en2：61.8%，10 篇）；4 篇真实 Claude Code PR 上对原文 **71.6%**（en2：75.4%）。
- **与 en2 正面对比 51.9%**：6 胜 3 负 3 平。13 篇调参集上是 57.5%：7 胜 2 负 4 平。
- 易读度 **4.13**，原文 3.95；AI 腔概率 **0.253**，en2 0.259，原文 0.30；保真风险 **0.530**，en2 0.543。
- 客观指标：
  - 超长句（>30 词）占比 **10.6% → 1.04%**（en2 为 0.69%）；
  - 平均句长 16.3 → 13.3 词；
  - 55 条补丁生效 54 条，唯一拒收的那条重复了被冻结的 `HttpMethod`，被守卫正确拦下；
  - 改动数字 0 篇，回退原文 0 篇。
- 12 篇的差异都在噪声内：en5 的整体胜率、保真风险和直接对比好于 en2，但真实 PR 子集略退、胜出篇数少 1 篇。调参集上 en5 明确好于 en2，因此采纳为默认。

下面第一～六节是 2026-11-11 第一代规则 en2 的完整记录，附录是第二代（en3 → en5）的迭代过程。

## 第一代（en2）结论

在 12 篇锁定测试集上，JEV 评委认为 no-ai-fluff-en 处理后的版本比原文好读：
- **12 篇里 10 篇胜出**，Wilson 95% 区间 55%~95%；
- 平均胜率 **61.8%**；中文版第一代封存集对原文是 63.7%。

客观指标：
- 12 篇都没有改动数字，没有一篇回退到原文；
- 59 条补丁生效 58 条，唯一拒收的那条被守卫正确拦下；
- 长句占比 10.6% → 0.7%。

逐条人工核对 JEV 报的保真疑点：**没有事实错误**，有两处推断性改写，需要如实披露（见第四节）。

## 二、调参过程（只在调参集上）

| 轮次 | 规则 | 生效 / 拒收 | 每句词数（原文 16.3） | 超 30 词长句（原文 3.5%） | 黑话 / 千词（原文 33.9） | 名词化 / 百词（原文 7.4） |
|---|---|---|---|---|---|---|
| r1 | en1 | 67 / 3 | 16.0 | 3.5% | 1.0 | 4.8 |
| r2 | en2 | 65 / 1 | **13.8** | **1.5%** | **0** | **4.6** |

r1 → r2 改了下面几处。到 r2 就停止调参，避免在 13 篇上过拟合：
1. **掩码**：“emails/messages”“Norway/Mexico”这类两个词用斜杠相连的写法，原先被当成路径冻结，宿主的正确补丁因此被拒（r1 的 3 条拒收里占 3 条）。现在当作正文。
2. **清理**：补丁拼接偶尔留下 “the a change” 这类重复冠词，增加了确定性清理。
3. **规则 en2**：r1 把黑话改干净了，但长句不拆。en2 给 [hard-clause] 加了三个具体触发条件：
   - 超过约 25 词就拆；
   - 主语和谓语之间夹着列表时，先说主干，列表另起一句；
   - 省略 that 的宾语关系从句补上 that。
   [empty-words] 补充了 “meaningfully、significantly” 这类副词。雷达的长句提示阈值同步改成 25 词。

## 四、保真：JEV 疑点逐条人工核对

JEV 的保真风险是监控项，不一票否决，与中文版相同。处理后版本的平均风险为 0.54（中文版封存集为 0.55）。风险单项超过 0.35 的 4 篇，我逐条看了补丁：

| 样本 | JEV 疑点 | 核对结果 |
|---|---|---|
| coding-02（jhipster） | 新增信息 0.59 | 无事实错误，但有两处改写方式值得披露：<br>① “Unchanged: monolith with JWT, session and reactive OAuth2” 被展开成三种 monolith 配置，这是对原文歧义列表的一种合理读法；<br>② “Lint …、`npm run check-types`、specs …, with no snapshot change” 被改成先后顺序的说法，语气略变 |
| coding-04（Bazaar） | 新增信息 0.45 | “[x] Pure tests: … (8)” 被改成 “The pure tests pass”：把打了勾的勾选框读成“通过”，属于推断性改写 |

## 五、局限（对外使用这些数字时必须带上）

1. **JEV 的英文问题集未经英文人工盲测校准**。中文版的 JEV 用人工盲测校准过，英文版没有英语母语评审，所以没做。问题措辞逐条照搬中文版用过的 rubric 版英文措辞。
2. **样本小**：测试集 12 篇，胜出篇数的 95% 区间是 55%~95%，场景层面只有 1~4 篇，不能下分场景结论。
3. **8 篇测试样本由 Claude 写成**，规则也由同一个会话里的 Claude 调。为此测试集在调参前写好并锁定，调参期间没有读，宿主用的是 DeepSeek，评委是 JEV。即便如此，出题人和调参人是同一方，这一点仍应披露。
4. 公式推导类（mixed）唯一一篇输给原文。按中文版的经验，理工场景是强项，英文版这一点还没有证据。

## 六、可用于英文宣传的事实（均可追溯到本报告；英文宣传片使用 en5 的数字）

- 在 12 篇测试集上，JEV 评委认为 en5 处理后的版本比原文好读的有 9 篇，平均胜率 63.1%。
- 4 篇真实的 Claude Code PR 描述上，对原文平均胜率 71.6%（3 篇胜出）。
- 0 篇改动数字，代码、路径、公式全部原样保留；唯一被拒的补丁重复了被冻结的 `HttpMethod`。
- 超过 30 词的长句占比从 10.6% 降到 1.04%；平均句长从 16.3 词降到 13.3 词；易读度 3.95 → 4.13。
- 往返翻译每篇约 5 秒、约 $0.0004。

使用时请同时注明：评委是 JEV（`typesafe/jev-1.14`），未经英文人工校准；测试集共 12 篇，已用过两次（en2、en5 各一次）。

## 附：2026-11-12 第二代迭代（en3 → en5，移植中文版第二代架构）

### 改动

和中文版用同一套架构，英文细节按英文语料调整：

- **雷达**：
  - 新增纯统计的 telegraphic sentence chain 提示。阈值：≥12 词、≥3 段、段均 3–8 词、虚词率 ≤0.30。英文的黑话密句是低虚词率的短语链（调参集 0.17–0.30，普通句子约 0.45），不是中文那种两三个字的碎片，所以阈值和中文不同。
  - jargon 词表提示可以关闭；`surface()` 评测统计仍用词表。
- **领域分诊**：英文版提示词，判断疑似电报句是否出自技术/工程语境，按整篇开关。
  - 是：走强化规则（en3 的 `AUDIT_EN3_DENSE`，en5 定稿为 `AUDIT_EN5_DENSE`），在 en2 上加了真术语 vs 包装黑话判据、往返稿照妖镜、第 12 类 `[telegraph-stack]`（只拆不补）和“即使觉得原文有误也不改”；
  - 否，或没有电报句：提示词与 en2 逐字相同。
- **生产路径**：和中文版一样走宿主模型握手。`prepare_rtt_draft` 新增 `draft_id` / `domain_triage`，CLI `prepare` 新增 `--draft-id` / `--domain-triage`，英文 agent.md 加了可选步骤。不连外部 API。
- **版本**：
  - en3 = 门控 + 强化规则，保留 jargon 词表；
  - en4 = en3 去掉运行时词表；
  - en5 = en4 调一轮：en4 把“只罗列具体事物的链可以不改”当成了连省掉的动词都不用补（en-tune-discussion-01 补丁 5→2），en5 改为“可以不拆，但省掉的动词和冠词仍按第 1 类补”。

### 结论

- en5 在调参集上明确好于 en2。在测试集上：对原文胜率 +1.3pp，保真风险更低，直接对比 6 胜 3 负。
