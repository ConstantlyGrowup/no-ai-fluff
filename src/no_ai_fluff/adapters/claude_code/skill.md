# /no-ai-fluff：交付前过一遍“说人话”审校

当你写完一篇面向人类阅读的中文交付物（终端里的长回复，或要落盘的 `.md` / `.html`），在交给用户之前：

1. 用 Agent 工具启动 `no-ai-fluff` 子智能体（`subagent_type: "no-ai-fluff"`），在提示里给它：
   - 草稿全文，或草稿文件路径；
   - 用户的原始问题（有的话）；
   - 出口：要写文件就写明 `exit=file` 和目标路径，否则是 `exit=terminal`。
2. 子智能体会调用 `prepare_rtt_draft` 和 `finalize_patched_delivery` 两个 MCP 工具，在独立上下文里完成审校，只把定稿交回来。
3. 拿到定稿后原样交付给用户，不要再自己润色一遍。交付时在聊天里附一句提示（见下一节）。

如果用户在调用时附带了文字或文件路径（`/no-ai-fluff path/to/draft.md`），就把它当作要审校的草稿。

## 交付后的一句提示（只在聊天里说）

- `exit=terminal`：先原样发出定稿正文，正文结束后空一行、加一条分割线，再附上这句：

  > 如果你觉得其中哪一段还是太绕、黑话太重，局部小改不够顺口，可以直接告诉我“整体重写”或者“只重写第 X 段”，我会只针对那一段彻底换种直白写法，代码、公式和数字仍一个不动。

- `exit=file`：这句提示**绝对不要写进目标文件**，文件里只有干净的定稿。在聊天里报告写到了哪个文件之后，再附上这句提示。

## 用户点名重写时：整段重写兜底

用户在定稿之后说“第 2 段重写”“这几句还是太绕，整段重写”，或者直接贴出几句话让你重写时，由你（主会话）亲自重写，不再调用子智能体。这一步不再是局部小改，可以整段重组语序，但必须守住下面五条：

1. **只改点名的部分**：只重写用户指出的那一段或那几句，文章其他段落一个字都不动。
2. **硬内容零改动，不编造**：代码块、行内代码、命令、文件路径、URL、LaTeX 公式、版本号和所有数字一字不差地保留；不补原文没写的机制、后果或前提条件；正负、前后、方向、顺序照原文写，即使你觉得原文有误也不改。
3. **真术语保留，包装词拆开**：换个普通说法会让懂行的读者误解成另一件事的，是真术语（例如 `P99`、幂等、死锁、SHA256），原样保留；换成“做、建、接、跟完、主线”之类的说法信息一点不少的，是包装黑话（例如底座、收口、打通、闭环、抓手、赋能），改成它实际指的动作。
4. **拆开压缩句和长难句**：用 `→`、`+`、`/` 代替连接词的写法，以及一串缺主语、缺连接词的短片段，改成有主语、有“先、再、然后、因为、所以”的完整句子；一句塞太多信息的长句拆成两三句。
5. **从头把意思说清楚**：不必在原句上修修补补，忠于原意、读着一口气能懂就行；也不要为了显得口语而扩写、加背景或升华。

重写完只发出改好的那一段（或那几句），并说明改的是哪一段；如果交付物是文件，用编辑工具只替换文件里的那一段。

前提：已经注册 MCP Server（`claude mcp add no-ai-fluff -- no-ai-fluff mcp`，或项目根目录有 `no-ai-fluff install claude-code` 生成的 `.mcp.json`），并在环境变量或 `.env` 里配置了 `OPENROUTER_API_KEY`（读不到时自动改用 `TENCENTCLOUD_API_KEY`）。
